Credenciales, rutinas y suites

Los bloques del lado del servidor que convierten ejecuciones sueltas en prueba reutilizable y repetible: bóveda de credenciales, perfiles de destino, rutinas versionadas, suites, evidencia fijada y un cliente de línea de comandos.

Bóveda de credenciales

Los secretos se guardan cifrados en el servidor (AES-256-GCM) y se referencian por id. Quien llama, incluso un modelo de IA, envía credentialSet: "gam-admin"; el servidor carga los valores y los steps siguen usando valueFromCredential por nombre de campo. Los valores son solo escritura: ninguna API, log, resultado o historial los devuelve.

PUT /v1/credentials/gam-admin        (Authorization: Bearer <SCRAPFORAI_API_KEY>)
{
  "boundOrigins": ["https://dev.example.com"],
  "values": { "loginUser": "...", "loginPassword": "..." },
  "tags": ["role:admin"]
}
POST /v1/explorations/run
{
  "targetProfile": "app-dev",
  "credentialSet": "gam-admin",
  "steps": [
    { "action": "goto", "url": "$targetUrl" },
    { "action": "fill", "selector": "#vUSER", "valueFromCredential": "loginUser" },
    { "action": "fill", "selector": "#vPASS", "valueFromCredential": "loginPassword" }
  ]
}
  • Vínculo por origen. Cada conjunto lista boundOrigins. Un fill de un valor de la bóveda en otro origen falla con CredentialOriginMismatch, aunque ese origen esté en la allowlist.
  • Quién escribe. POST/PUT/DELETE /v1/credentials/:id exigen el bearer token; una sesión de la consola web no alcanza. GET devuelve solo ids, orígenes, nombres de campos, tags y último uso.
  • Clave. SCRAPFORAI_VAULT_KEY (32 bytes, base64) o un vault.key generado en el directorio de datos. Sin la clave la bóveda no se puede leer.
  • MCP. La herramienta run_exploration no tiene el campo credentials, así que el modelo nunca escribe ni ve un secreto. list_credential_sets muestra lo que existe.
  • Legado. La API REST todavía acepta credentials inline (obsoleto, queda en el log). Use ALLOW_INLINE_CREDENTIALS=false para exigir la bóveda.

Perfiles de destino

Un perfil da nombre a una aplicación y ambiente, aporta el targetUrl por defecto y lista los conjuntos de credenciales que una ejecución puede usar. Nunca amplía ALLOWED_TARGET_ORIGINS: un baseUrl fuera de ella se rechaza.

PUT /v1/targets/app-dev
{
  "name": "My app (dev)",
  "environment": "dev",
  "baseUrl": "https://dev.example.com/app",
  "platform": "genexus",
  "credentialSets": ["gam-admin", "gam-readonly"],
  "flags": { "maxSessionsPerCredential": 1 }
}

Úselo con "targetProfile": "app-dev" en una ejecución. maxSessionsPerCredential (por defecto 1) es cuántas sesiones simultáneas puede tener una credencial.

Rutinas guardadas

Una rutina es dato, así que se puede guardar, versionar y revisar. Cada cambio es una versión inmutable (v1.json, v2.json); guardar contenido idéntico no crea nada. El sha256 de cada versión se verifica en cada lectura.

PUT /v1/routines/crud-sales
{ "title": "Sales CRUD", "targetProfile": "app-dev", "credentialSet": "gam-admin",
  "steps": [ { "id": "auth", "action": "include", "routineId": "login", "version": 1 },
             { "id": "open", "action": "click", "selector": "#menu-sales" } ],
  "teardown": [ { "id": "bye", "action": "goto", "url": "https://dev.example.com/app/logout" } ] }

PUT /v1/routines/crud-sales      { "fromJobId": "job_abc123" }      // save a run that worked
POST /v1/routines/crud-sales/run?version=2
  • Se rechazan los secretos. Un literal igual a un valor de la bóveda, o con forma de clave de API, JWT o token, se rechaza al guardar (422).
  • fromJobId guarda los steps de una ejecución que pasó, mientras su evidencia todavía exista.
  • Estado: draft, active, quarantined, retired. Cambiarlo es una nueva versión. Las suites ejecutan active y quarantined por defecto: una rutina en cuarentena se ejecuta y se informa aparte, pero nunca cambia el veredicto.
  • Apunte ROUTINE_LIBRARY_DIR dentro de un repositorio git para revisar rutinas en pull requests.

Include y teardown

{ "action": "include", "routineId": "login" } expande otra rutina guardada en su lugar. Los ids de los steps expandidos reciben el prefijo del id del include (auth.submit). Hasta 3 niveles; los ciclos se rechazan al guardar; la rutina incluida debe ser del mismo perfil de destino y no estar retirada. Sin version se usa la versión actual, así que fíjela para una prueba reproducible. Las versiones realmente usadas quedan en result.includes.

teardown es una lista de steps que siempre se ejecuta después de los steps, pasen o fallen (como un finally): primero el teardown propio, luego los de las rutinas incluidas, la última incluida primero. Los fallos de teardown aparecen en result.teardown y teardownStatus; nunca cambian el status de la ejecución ni reemplazan el fallo de un step.

Suites

Una suite ejecuta varias rutinas guardadas, multiplicadas por conjuntos de credenciales y perfiles de destino. Iniciarla responde 202 al instante y corre en segundo plano.

POST /v1/suites                                  -> 202 { "suiteRunId": "suite_..." }
{
  "name": "nightly",
  "items": [ { "routineId": "crud-sales" }, { "routineId": "report-activity" } ],
  "variants": { "credentialSets": ["gam-admin", "gam-readonly"], "targetProfiles": ["app-dev", "app-qa"] },
  "failFast": false
}
GET /v1/suites/suite_...?wait=30                 // blocks up to 55 s until it ends
  • Cada ejecución tiene una variantKey legible, por ejemplo crud-sales@v2/cred:gam-admin/target:app-qa. Las versiones de las rutinas se fijan cuando la suite empieza.
  • Un solo veredicto: green (salida 0), red (1, una ejecución falló) o infra-error (2, una ejecución no pudo correr, no corrió nada o se canceló).
  • Una sesión por credencial. Las ejecuciones que comparten un conjunto de credenciales nunca se superponen; una ejecución directa que necesita una credencial ocupada recibe 409 CredentialInUse.
  • failFast deja de iniciar ejecuciones en el primer rojo; el resto queda listado como no ejecutado. POST /v1/suites/:id/cancel detiene la suite.
  • MAX_PARALLEL_JOBS es el pool compartido; INTERACTIVE_RESERVED_SLOTS (por defecto 1) nunca se dan a las suites.

Retención y evidencia fijada

La evidencia expira tras ARTIFACT_RETENTION_HOURS (4 h), salvo que la ejecución use options.retention: "standard" (STANDARD_RETENTION_DAYS, 30 días). Para conservar la prueba para siempre, fíjela:

POST /v1/runs/job_abc123/pin
{ "reason": "proof for REG-209", "ref": "npdev:REG-209" }

GET /v1/runs/job_abc123/manifest   // sha256 of every file, re-verified now

Fijar mueve la ejecución a un almacén que nunca se limpia (limitado por PINNED_EVIDENCE_MAX_MB; sobre el límite recibe 409 y no se borra nada), descarta el trace pesado salvo con keepTrace y rechaza evidencia cuyo manifiesto ya no coincide con los archivos. El manifiesto prueba que los archivos no cambiaron; no prueba que la prueba fuera correcta.

La línea de comandos scrapforai

npm run cli -- run crud-sales --version 2 --json
npm run cli -- suite nightly.json
npm run cli -- routines list
npm run cli -- runs show job_abc123
npm run cli -- pin job_abc123 --reason "proof" --ref npdev:REG-209

La CLI habla con la API REST usando la clave del .env (nunca por la línea de comandos). Códigos de salida: 0 pasó, 1 una prueba falló, 2 cualquier otra cosa (API caída, argumentos inválidos, ejecución que no pudo correr). Con --json imprime exactamente un objeto JSON en stdout, versionado por cliSchema; el progreso va a stderr.

{ "cliSchema": 1, "command": "run", "exitCode": 1,
  "result": { "jobId": "job_...", "status": "failed", "failedStepIndex": 2, "error": { "type": "StepExecutionError", "message": "..." } } }

Herramientas MCP

Flujo recomendado para un agente de IA: list_targets → inspect_dom → run_exploration → save_routine (con fromJobId) → luego run_routine o run_suite + get_suite_result.

HerramientaPropósito
list_credential_sets, list_targetsDescubrir lo que ofrece el servidor (nunca valores secretos).
inspect_dom, run_explorationExplorar una página y ejecutar steps.
list_routines, get_routine, save_routine, run_routineLa biblioteca de rutinas.
run_suite, get_suite_resultIniciar una suite (vuelve al instante) y esperarla con waitSeconds.
get_runResumen (y opcionalmente el resultado completo) de una ejecución pasada.
