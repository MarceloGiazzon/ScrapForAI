| | |
|---|---|
| **Status** | Proposal. **Nothing in the NPDev repository was changed**, and ScrapForAI has no `serverClock` profile field yet: it waits for an endpoint that does not exist. |
| **ScrapForAI side** | The `setClock` step is done (browser clock only). The hook below is the part of T7.3 that needs NPDev. |
| **Related** | [ROADMAP-2027.md](ROADMAP-2027.md) T7.3 |

## The problem

`setClock` changes the clock the **page** sees (`Date`, timers). A GeneXus date rule (due dates, "expired offer", age of a record, month-end closing) almost always runs on the **server**,
which keeps reading the real date. A test of such a rule under `setClock` would pass or fail for the wrong reason, which is why the run report prints, when a clock was changed:
*"Only the browser's clock was changed. Rules that run on the server saw the real date, so this run does not prove them."*

## Proposal

A development-only endpoint of the generated application that sets the date the server's business rules use, for the current tenant or session:

```
PUT  /dev/clock    { "now": "2030-01-31T23:59:50-03:00" }     -> 204
GET  /dev/clock                                              -> { "now": "...", "fixed": true }
DELETE /dev/clock                                            -> 204   (back to the real clock)
```

Requirements, in order of importance:

1. **Off unless explicitly enabled for a development environment** (a build flag or an environment variable that production builds do not carry). It must answer 404 when disabled, not 403.
2. **Scoped**: per session or per tenant, never global, so two people testing at once do not move each other's date.
3. One place in the application reads "today" (a single date provider), and the endpoint sets that provider. Rules that call the database's own `NOW()` stay real; the document should say which they are.

## What ScrapForAI would add once it exists

- A target-profile field `serverClock: { setUrl, resetUrl }` (same-origin, inside the allowlist, only for `environment: dev|qa`).
- `setClock` gets `server: true`: it calls the endpoint with the same instant, records it in `result.clock`, and calls `DELETE` in the run's teardown even when the steps fail.
- The report line about the server clock disappears for those runs.

Until then the limit is stated, not hidden.
